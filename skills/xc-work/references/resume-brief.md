# Resume Briefs for Cross-Session Handoff

Compact derived view of one or more managed runtime trees, generated by `scripts/resume_brief.py` from read-only runtime commands only. A resume brief tells a main session what was running, what blocked, what is ready, and which artifacts exist, without opening orchestration state directly.

## Activation Policy

- Activated for cross-session work. Regenerate the brief at each main-session handoff; never reuse a stale one.
- The brief is a derived view, never a source of truth. It does not replace runtime state: scheduling, blackboard, and integrity stay engine-owned, and runtime commands and artifacts remain authoritative.
- Generation is read-only. The script never mutates a tree and never bypasses engine-owned orchestration boundaries.

## Generation

`python skills/xc-work/scripts/resume_brief.py --tree <runtime-xml> [--tree ...] [--workbench <work-order-dir>]`

- State is gathered only through public read-only runtime commands (`snapshot`, `artifacts`); the tree file is never opened by the script.
- Output is deterministic compact JSON: `schema_version`, `ok`, and `briefs` with sorted keys and bounded lists.
- Unreadable or sealed trees are skipped per tree with a stable `skip_reason`; invalid input returns `ok:false` with a stable error code.

## Brief Sections

- `status_counts`, `running_nodes`, `blocked_nodes` (id + reason), `awaiting_dynamic_groups`
- `ready_leaves` (top 10) and `recent_terminal_results` (top 10, node id + status + summary snippet)
- `declared_artifacts` from the runtime artifacts command
- `decision_registry` path pointer when the workbench holds a registry file, otherwise null
- `next_actions`: bounded suggestions derived from blockers and ready leaves

## Consumption

- On handoff, replay the brief, then resume through the runtime: request the next ready batch and handle blockers through `references/recovery-patterns.md`. Never schedule from the brief alone.
- Verify the brief against current runtime state before consequential action; a brief can be stale the moment it is written.
- `next_actions` are suggestions. Gates, user decisions, and recovery policy still come from the owning workflow and the runtime.
- A skipped tree (unreadable, sealed, or non-runtime) is reported, not repaired; use the runtime's own diagnostics before further action.
