# Emberdeep — a small 2D sandbox

Emberdeep is a playable, offline 2D sandbox inspired by Minecraft. You arrive in a quiet meadow,
chop wood, craft tools, dig into a cave system, survive the dark, and follow a small material
progression down to the Ember ore at the bottom of the world.

Open `index.html` directly in a browser. There is no build step, no package manager, no external
library, font, image or network request: all art, sound and logic are generated by the page itself,
and it runs from `file://`.

## Start a game

1. Open `index.html`.
2. Press **Enter world** (or **Continue** when a saved world exists).
3. Hold **left mouse** on a tree trunk. Gather wood, press **E**, and craft planks, sticks and a
   workbench.

The journey tracker in the top-left corner always states the next objective and a hint for it. The
whole arc is: gather wood → build a workbench → craft a wooden pickaxe → reach the stone tier → light
a torch → forge an iron pickaxe → mine ember → raise the Ember Beacon.

## Controls

| Input | Action |
| --- | --- |
| `A` / `D` or `←` / `→` | Walk left and right |
| `Space` | Jump (hold briefly for a little extra height) |
| Hold left mouse | Mine the block under the pointer within reach. The block must touch air, and your pickaxe tier must be high enough. |
| Left mouse on a hollow | Attack the hostile hollow under the pointer |
| Right mouse | Place the selected block into an empty tile next to solid ground |
| `1` – `9` or mouse wheel | Select a hotbar slot |
| `E` | Open or close the inventory and crafting panel |
| `Esc` | Pause menu (resume, save, controls, mute, new world, quit to title) |
| `H` | Open or close the controls panel |
| `M` | Mute or unmute procedural sound |

The same controls are available inside the game: the pause menu has a **Controls** entry, and the
title screen links to it before you start.

## What to expect

- **A world you can read.** A minimap, coordinates and a depth label keep you oriented. The top-left
  tracker tells you what to do next; the clock tells you how long until night.
- **Mining with real rules.** Softer blocks break quickly; stone needs a wooden pickaxe, iron ore
  needs a stone pickaxe, and ember ore needs an iron pickaxe. Better tools break blocks faster, and
  blocks must be dug from an exposed face.
- **Crafting with stations.** Basic recipes work anywhere. Tools, a furnace, stone bricks and the
  Ember Beacon need a workbench placed nearby; smelting ore needs a furnace nearby. Locked recipes
  state why they are locked.
- **Light and night.** Caves are dark and torches light them. Hollows appear in darkness at night,
  damage you on contact, and fade at dawn. Health regenerates slowly after a few seconds out of combat.
- **Building.** Every mined block can be placed again. Build a shelter, a bridge, a lit base, or
  somewhere to put the beacon.
- **Saving.** The world, inventory, journey and clock are saved to local storage automatically every
  20 seconds and whenever you pause, quit to title or close the page. The title screen shows the saved
  day, blocks mined, play time and how long ago it was saved. If storage is unavailable or corrupt,
  the game reports the problem and offers a fresh world rather than failing silently.

## Goal

The deep band near the bottom of the world holds Ember ore. With an iron pickaxe, mine three ember
ore, refine the shards at a furnace with coal, then craft the Ember Beacon from shards, iron and stone
bricks and place it. Lighting the beacon completes the journey; the sandbox continues afterwards,
with the world still saved.

## Checks

From the project root:

```console
node --test "tests/**/*.test.js"
python tools/page_check.py
```

`node --test` covers world generation, the block and tool model, lighting, player physics, inventory,
crafting, progression, hollows and saving. `python tools/page_check.py` checks the page shell, that
every served file is local (no external references), and that the game boots in headless Chrome with
a visible canvas and a ready status marker. Add `--screenshot <path>` to keep a capture.

An optional interaction check drives the installed Chrome over the DevTools protocol with real
dispatched pointer and key input, then reports mining, placement, saving/reloading, first run and
console health as JSON:

```console
node tools/browser_check.js
```

It creates a temporary profile and screenshot directory; pass `--shots <dir>`, `--profile <dir>` or
`--out <file>` to choose locations, and `--chrome <path>` if the browser is not in a default install
location.

## Layout

```text
index.html          page shell and classic script load order
css/style.css       HUD, hotbar, menus and canvas frame
js/config.js        shared constants, block and item ids
js/rng.js           deterministic noise and random helpers
js/blocks.js        block/item registry: hardness, tiers, drops, light, palettes
js/world.js         seeded world generation, block access, RLE world codec, minimap sampling
js/light.js        day factor and sky/torch light grid
js/player.js        movement, collision, health, reach, respawn
js/inventory.js     slots, hotbar, stacking, moving items
js/crafting.js      recipes and station proximity
js/progression.js   the eight-stage journey
js/mobs.js          night hollows
js/save.js          versioned local save with validation
js/render.js        procedural textures, sky, entities, particles and lighting
js/audio.js         procedural sound effects
js/ui.js            HUD, hotbar, minimap, inventory, menus and toasts
js/input.js         keyboard and real pointer input
js/main.js          boot, fixed-step loop, interactions, saving
tests/              node test suite
tools/              page and browser checks
```

## Notes

- The game targets a desktop browser with a mouse and keyboard.
- No project build tooling is required or used.
- Audio starts after the first click, because browsers require a gesture before audio can play.
