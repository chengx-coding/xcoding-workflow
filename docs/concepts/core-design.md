# Core Design

This page introduces the XC core design and points to the document that defines it.

The XC core design is the project's formal statement of what XC's core is: the principles, invariants, and decision criteria that its five dimensions together rest on, and the shared frame of reference that people and agents use when they judge a later change. This page orients a reader toward that statement; it does not make it.

The authoritative core design is the document at `.xcoding/docs/core-design.md`, whose H1 is `Xcoding Workflow 核心设计`. It is the project's single normative core design, maintained in exactly one place under the workshop's own context repository. Every other location that needs it references it by that path and title and never copies it into a second copy, so no independently maintained duplicate exists to drift out of step. Any adjustment, improvement, or change to that document requires the user's prior confirmation before it takes effect.

This overview describes where the core design lives and how to use it with the rest of the public documentation. It does not define the core design, and it deliberately does not repeat its content: on any difference between this page and the authoritative document, the authoritative document governs.

For the surrounding context, read [architecture](architecture.md) for canonical sources and ownership boundaries, [workshops and features](workshops-features.md) for the workshop, work orders, and feature baselines that the first dimension rests on, and [evolving the workflow](../workflows/evolving.md) for how a deliberate change to the workflow itself is made.
