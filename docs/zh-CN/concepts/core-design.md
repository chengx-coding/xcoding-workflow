# 核心设计

本页介绍 XC 的核心设计，并说明它依据什么。

XC 核心设计是 XC 对「XC 的核心是什么」的正式陈述：它给出五个维度共同依据的原则、不变量与判定标准，也是人与智能体在判断一次后续改动时共用的同一套参照。本页以公开解释材料的方式概括这份陈述。

这份设计建立在五个维度之上。工作单即工作区：每一份被委派的实质工作都拥有一个持久、自包含、有明确拥有者的目录。以编排树规划执行：编排树承载这份工作怎样被规划、推进、约束与观察。项目桥接：把通用流程与某一个项目的事实连接起来的唯一读取点。智能体技能集合：处理复杂任务所需的可复用能力的集合与边界。面向软件开发的专用设计层：位于通用设计之上、把它适配到软件开发场景。

它们之间的依赖是单向的：工作单是承载单位，编排树是执行规划，桥接是项目事实的入口，技能集合是能力供给，软件开发专用层是应用特化。工作单为编排树提供持久化位置与产物归属；编排树为技能集合提供可复用的流程载体；桥接为其余四者提供项目专属事实；软件开发专用层同时受通用流程与项目桥接约束。

本概览把贯穿全部五个维度的义务归纳为三项。改动必须按整体架构判断，而不只按其局部症状判断——一次让局部症状消失、却让整体变得更纠缠的改动，不应因为局部方便而被并入。改动必须成比例：当更小的正确修复已经足够时，应当复用既有机制，而不是新增命令、状态、配置面或节点类型。规范来源先行：派生物与生成物永不手工编辑，且不得产生需要同步的第二权威。

对整个核心设计的任何调整、改进或变更，都必须在生效前先取得你的确认，而不是由实现者在其他工作中顺手修改。

本概览概括这份核心设计，使读者能把其余公开文档放在它的框架里理解。它是解释，而不是设计本身，也不声称取代它。
